# Канал обновлений dev

При каждом push в dev Windows Actions запускает исходные тесты, собирает CEF
и диалог папки, получает официальные embeddable CPython 3.13 и .NET 8 Windows
Desktop, добавляет VC Runtime и создаёт полный portable ZIP. `main` не меняется.
Модели, игры, проекты, базы и секреты в ZIP не входят. Для первого запуска нужны
включённые GitHub Actions и разрешение workflow на запись Contents; пользовательский
API-ключ не нужен. GitHub Releases должен быть доступен без авторизации.

Сначала публикуется полный ZIP в prerelease `dev-<github.run_id>`, затем
`dev-latest/dev-update.json` указывает на этот конкретный архив с SHA-256,
размером, commit SHA и номером сборки. Во время сборки нового коммита пользователи
продолжают получать последнюю готовую сборку. Сбой тестов, сборки или загрузки
архива не перемещает канал. Старый параллельный запуск не публикуется поверх
нового dev HEAD. Номер версии может оставаться прежним: обновление различает коммиты.

В лаунчере проверка идёт в фоне при запуске. Установка запускается пользователем
одной кнопкой; активные перевод/анализ/установка модели или CLI блокируют её.
Проверка и загрузка используют HTTPS и фиксированный репозиторий
UFrimNe/RenPyTranslator. Серверы редиректа допускаются только GitHub.
Без интернета локальный перевод продолжает работать. SHA-256 защищает от
повреждения загрузки; доверие к публикациям основано на HTTPS и правах репозитория,
отдельной криптографической подписи сборок пока нет.

Загрузчик проверяет внешний SHA-256, размеры, платформу/канал и состав ZIP.
Установщик повторно проверяет SHA-256 архива и каждого файла. Не допускаются
выход за корневую папку, Windows ADS/зарезервированные имена, дубликаты с разным
регистром, symlink/junction и файлы вне разрешённых папок.

Перед закрытием окна установщик получает собственную копию Python во временной
папке. Он ждёт завершения backend, CEF и bootstrap по Windows process handles,
захватывает update/desktop/operation locks и только затем заменяет файлы.
Временная копия интерпретатора позволяет заменить и комплектные среды запуска.
При невозможности закрыть процессы файлы не меняются.

До каждой замены создаются резервная копия и журнал намерения. Ошибка замены
откатывает выполненные операции; незавершённый журнал проверяется при следующем
запуске. Последняя копия хранится в data/updates/rollback. Устаревшие файлы
удаляются только если они записаны в предыдущем манифесте и не изменены.
Пользовательские файлы вне состава обновления сохраняются. Папки data,
runtime/local_ai и внешние игры никогда не принадлежат обновлению.
Загрузки и резервная копия требуют дополнительного места на диске.

Логи: data/logs/updater.log, результат: data/updates/result.json; журнал отката
и манифест включены в диагностический ZIP. При повреждении самой среды Python
из-за аварийного выключения остаётся восстановление из полного ZIP.

Ручная сборка на Windows:

```powershell
./app/desktop/build.ps1
# prepare-runtime.ps1 предназначен для CI и требует RUNNER_TEMP
./app/desktop/prepare-runtime.ps1
python app/tools/package_release.py --build-id <40-digit-commit-sha> --build-number <github-run-id>
```

Не загружай zip исходников в канал и не редактируй dev-update.json вручную.
Повтор workflow для того же коммита не требует обновления уже установленной
программы. Для изменения программы нужен новый коммит.
